# 002 · 竞技场 v0.1 与动作空间设计教训（2026-09-27）

> 产物：`scripts/arena.py`（pygame 竞技场 + numpy 手写 MLP）· `out/demo-random-init.gif`（随机权重演示）

## 建起来的东西

- 640×480 场地、4 个掩体、双坦克（蓝/红），HP 100、命中 -25（4 发带走）、开火冷却 18 步、一局上限 1800 步；
- 观测向量 20 维（己方/敌方位置朝向血量、相对位置距离、最近敌弹 dx/dy/vx/vy、冷却、剩余时间、常数项），全部归一化到 [-1,1]；
- MLP 20→128→128→5，numpy 手写，He 初始化，19,845 参数（比 9 输出版少 516 个）；
- 两个坦克各持一份随机权重互打，动作为 softmax 采样（探索模式）。

## 实验发现①：动作空间设计直接决定能不能学（本日最大教训）

**初版「8 方向移动 + 开火」9 动作方案失败**：开火方向 = 朝向 = 最近移动方向，而移动只有 8 个方向 → **瞄准被量子化到 45°**。敌坦克 24px 宽，在 300px 距离上张角只有 ~4.6°，45° 的瞄准粒度下随机命中率≈0——实测 3 局 5400 步 0 命中。

**后果不止是演示难看**：命中是唯一的奖励来源，命中率≈0 = 奖励信号不存在 = 训练无从谈起。这是稀疏奖励问题的极端版，而且**根因在游戏设计，不在网络**。

**修复：改 5 动作转向制**（左转/右转/前进/后退/开火），炮塔朝向连续（每步 3.4°），指哪打哪。同样随机大脑，实测每局 0~2 命中——奖励信号稀少但存在，可学。

> 认知沉淀：**动作空间的粒度要和任务精度匹配。离散化决策维度时，先算一下目标在最远典型距离上需要多细的分辨率。**

## 实验发现②：初始掩体布局堵死了主弹道

初版 4 个掩体里有两个正好压住出生点中线，面对面站桩互射的验证用例 400 步 0 命中——先怀疑代码 bug，定位后是子弹出膛就撞掩体。**教训：验证游戏机制要用"明知道应该发生什么"的脚本化用例（面对面互射必死人），不能用随机行为去碰。**

## 随机基线（训练前的对照组）

```
随机权重 3 局：全部平局（1800 步打满），命中 0~2 发/局，血量基本不掉
```

训练后的对比指标：胜率、命中率（hits/shots）、平均存活步数、场均血量差。
