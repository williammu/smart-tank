## 一句话

从克隆权重出发自对弈 REINFORCE（−logP×A），再靠**逐步奖励 shaping** 治掉"顶墙/站桩"两种行为病——最终存档 vs 规则老师 **27胜51平22负**（SL 克隆体是 19胜50平31负），路线 C 的题眼达成。

## rl-v1 配方与教训

- 奖励：命中+0.2 / 挨打−0.2 / 胜+1 / 负−1 / 平−0.05（**反僵死**）；A = 全局回报，批内归一化当 baseline；熵奖励 β=0.005；梯度裁剪 5.0；Adam lr 1e-4；每 64 局更新一次；
- 教训①：REINFORCE 噪声大——月考 score 在 −4~+13 间荡秋千，**最佳 checkpoint 存档机制是刚需**（任凭它荡，只留山顶）；
- 教训②：运维事故——旧炉 `job_kill` 延迟生效多跑了 170 轮，期间冒烟测试覆盖了它的最佳存档。**军规：正式跑之前先备份存档，冒烟测试用独立输出路径**。

## rl-v2：奖励工程治行为病（不改一行控制逻辑）

用户实机观察到的两个病：脸贴掩体死顶（顶墙率 42%）、原地发呆。药方全是奖励信号：

```
① 顶墙流血：想动但位移≈0 → 每步 −0.01（面壁 100 步 ≈ 白输一局）
② 站桩流血：近 10 步累计位移 < 3px → 每步 −0.01
③ 接近有奖：与敌人距离缩短 +0.0005/像素（绕路的动机）
④ return-to-go（γ=0.99）：每步只背"从它往后"的锅——锅精准落在发病步骤上
```

疗效：顶墙率 42%→~10% ✅；站桩率 77.8%→65.2%（口径含"原地转向瞄准"，有水分）⚠️；战绩不降反升 ✅。

## 认知沉淀

1. **奖励工程是 RL 的"需求文档"**：行为病不用改代码，让"发病行为"变疼、让"期望行为"有钱赚，网络自己长出新行为——涌现而非编程；
2. **信用分配三级跳**：全局共背一锅（v1）→ return-to-go 只背身后的锅（v2）→ 价值网络当裁判（A3C/PPO，下一步）；
3. **护栏指标**：改奖励时主战指标（vs 老师战绩）必须盯死——奖励工程的经典翻车是"指标优化了，本体丢了"；
4. 与 AlphaStar 流程对照：人类回放→BC→自对弈 RL→联赛。我们已走完前三环的缩比版，下一步候选：critic 头（价值裁判）、对手池/联赛、战争迷雾+LSTM。
